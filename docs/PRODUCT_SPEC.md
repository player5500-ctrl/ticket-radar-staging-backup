# 追票雷達 Ticket Radar — Product Spec

## 1. 文件狀態

- 階段：Phase 0
- 版本：0.1
- 產品類型：合法合規的演唱會與活動購票準備助手
- 預設語系：繁體中文
- 預設時區：`Asia/Taipei`
- 日期儲存：UTC；顯示時依使用者時區轉換

## 2. 產品定位

Ticket Radar 協助使用者：

1. 搜尋歌手、團體、活動、場館與城市。
2. 追蹤歌手、收藏活動、整理各售票階段。
3. 建立提醒與匯出 ICS 行事曆。
4. 建立購票任務與準備清單。
5. 在本機加密保存固定購票資料。
6. 由使用者主動按下按鈕後，填入支援平台的固定欄位。
7. 在明確同意後，偵測模擬成功頁、遮蔽敏感資訊並保存本機截圖。
8. 保存購票紀錄，但不把「訂單成立」誤判為「付款成功」。

Ticket Radar 不是自動搶票工具，不監控票量，也不替使用者作出購票決定。

## 3. 不可跨越的產品邊界

下列能力不進入任何版本的自動化流程：

- 自動刷新票券頁面。
- 自動選票種、選座位、切換場次或排隊。
- 自動送出訂單或付款。
- 自動輸入、破解 CAPTCHA 或回答防機器人問題。
- 多帳號批次操作。
- 監控或掃描剩餘票量。
- 繞過售票平台限制、風控或服務條款。
- 儲存平台密碼、OTP、信用卡安全碼、網路銀行資訊或 CAPTCHA。
- 不經使用者按下「填入資料」便修改售票頁面欄位。

擴充功能只能填入固定身分／聯絡欄位。票種、場次、座位、數量、條款、驗證與送出都必須由使用者親自完成。

## 4. MVP 使用者

### 4.1 一般使用者

- 搜尋與收藏活動。
- 追蹤歌手。
- 建立購票任務、檢查清單與提醒。
- 建立僅保存在擴充功能本機的購票資料組。
- 在 Demo 售票頁主動觸發填入。
- 建立與查看購票紀錄。
- 匯出與刪除自己的資料。

### 4.2 管理員

- 管理歌手、別名、場館、活動、售票階段與平台資料。
- 確認活動資料來源與最後確認時間。
- 管理 Adapter 版本狀態。
- 查看錯誤回報、通知紀錄與稽核紀錄。

### 4.3 MVP 身分策略

Phase 1 先使用可替換的本機 Demo 身分提供端，讓核心流程可在無外部帳號時執行。正式環境必須換成支援安全 session、CSRF 防護與角色控管的身分提供端。管理權限只由 Workers API 判斷，不接受前端自行宣告 `admin`。

## 5. MVP 核心流程

```text
搜尋活動
→ 查看官方來源與售票時間軸
→ 收藏活動
→ 建立購票任務與準備清單
→ 設定提醒／匯出 ICS
→ 開啟 Generic Demo 售票頁
→ 使用者在擴充功能選擇本機資料組
→ 使用者主動按下「填入資料」
→ 使用者逐項檢查並手動送出 Demo 訂單
→ 擴充功能在已同意的前提下偵測成功頁
→ 解析訂單狀態並遮蔽敏感資訊
→ 保存本機截圖
→ 透過受限 API 建立購票紀錄
→ PWA 顯示遮罩後的購票紀錄
```

## 6. Phase 1–5 MVP 功能

### 6.1 活動搜尋與詳情

- 搜尋歌手、團體、歌手別名、活動、場館、城市。
- 依平台、日期範圍、售票狀態篩選。
- 追蹤歌手、收藏活動。
- 活動來源限管理員手動、使用者手動、官方網址貼入，以及 Mock 公告解析服務。
- 所有活動頁固定顯示：
  > 活動資料請以主辦單位及售票平台官方公告為準。

### 6.2 售票時間軸與提醒

- 一個活動可有多個 `ticket_sale_windows`。
- 支援登記、預售、抽選、一般售票、付款、取票與活動提醒。
- 支援 7 天、1 天、1 小時、10 分鐘、1 分鐘前及自訂時間。
- MVP 通知：Web Push、ICS；Email 使用可觀察的 Mock provider；LINE 僅保留介面。
- 無 Email／LINE 金鑰時，不可阻塞其他流程。

### 6.3 購票任務與準備度

- 任務保存預算、最大張數、可接受場次、三個區域順位與備註。
- 檢查清單採明確項目；完成率為 `已完成項目數 / 適用項目數`。
- 若沒有適用項目，顯示 0%，不可除以零或顯示 100%。

### 6.4 購票資料組

- 購票資料預設只保存於擴充功能的 `chrome.storage.local`。
- 敏感欄位使用 Web Crypto API 加密，PIN 經 KDF 派生金鑰。
- PWA 只知道擴充功能連線狀態與資料組顯示名稱，不取得解密後個資。
- 禁止欄位由共用 Zod schema 與擴充功能雙重攔截。

### 6.5 Generic Demo Adapter

- 提供受控 Demo 售票頁與成功頁，完整驗證偵測、填入、手動送出、遮蔽、截圖與紀錄。
- Adapter 找不到 selector 時回傳逐欄結果，不拋出造成頁面崩潰的未處理例外。
- 填入動作只由擴充功能 popup 中的明確使用者點擊觸發。

### 6.6 購票紀錄

- 記錄活動、平台、遮罩訂單編號、張數、座位／區域、成立時間、付款狀態、付款期限、取票狀態、截圖檔名與備註。
- 成功頁偵測預設狀態為「訂單已成立」或「狀態待確認」；只有明確且可信的付款文字才可標示「已付款」。
- 雲端不保存原始截圖；MVP 只保存本機檔案與遮罩後中繼資料。

### 6.7 管理後台

- 基本 CRUD：歌手、別名、場館、活動、售票階段、平台。
- Adapter 版本狀態、活動來源／確認狀態、使用者錯誤回報、通知紀錄、audit log。
- 管理員關鍵異動必須留下 before／after 的安全摘要，不記錄秘密或完整個資。

## 7. MVP 主要頁面

| 頁面        | 主要工作                                       |
| ----------- | ---------------------------------------------- |
| 首頁        | 統一搜尋、即將開賣、追蹤歌手、最近新增         |
| 搜尋結果    | 關鍵字、城市、日期、平台、狀態篩選             |
| 活動詳情    | 官方來源、時間軸、收藏、建立任務、官方連結     |
| 購票任務    | 準備度、清單、預算、票數、場次／區域順位、提醒 |
| 作戰模式    | 大字倒數、官方連結、順位與清單；沒有自動購票   |
| 購票資料    | 資料組說明與擴充功能連線入口                   |
| 購票紀錄    | 訂單與付款／取票狀態、截圖檔名                 |
| 設定        | 時區、通知、隱私、匯出、刪除、帳號刪除         |
| 管理後台    | 內容管理、回報、通知與稽核                     |
| Demo 售票頁 | 供 Generic Demo Adapter 驗證的安全測試頁       |

## 8. UI 與無障礙

- 手機優先，底部導覽為首頁、搜尋、任務、紀錄、我的。
- 深色模式。
- 互動控制的觸控區域至少 44 × 44 CSS px。
- 表單欄位有可見標籤、錯誤提示與鍵盤焦點樣式。
- 狀態同時使用文字／圖示／顏色，不只使用顏色。
- 倒數計時支援 `prefers-reduced-motion`，並提供可讀文字。
- 官方連結清楚標示將離開 Ticket Radar。

## 9. 成功指標

MVP 的完成以流程可用與安全限制可驗證為準：

- 使用者能用別名找到 Seed 活動。
- 能完成收藏、任務、提醒與 ICS 匯出。
- Demo 資料組可加密保存，解鎖後由使用者按鈕觸發填入。
- Demo 訂單必須由使用者手動送出。
- 成功頁能遮蔽測試敏感資料、避免重複截圖並建立紀錄。
- 管理員 CRUD 與 audit log 可運作。
- `lint`、`typecheck`、單元、整合、build 與 Playwright E2E 全部通過。

## 10. MVP 不包含

- 未經授權的售票網站爬蟲或票量監控。
- 正式的 KKTIX／TixCraft 自動化保證。
- 雲端同步購票資料明文或訂單截圖。
- R2 圖片儲存。
- 正式 Email／LINE 發送（沒有憑證時使用 Mock／disabled provider）。
- 自動付款、排隊、選票、送單或 CAPTCHA 操作。

## 11. 驗收原則

1. 不以空白頁、假按鈕或只有 UI 的 mock 視為完成。
2. 每個核心功能必須有資料流、錯誤處理與測試。
3. 所有破壞性或高風險行為都必須是預設關閉。
4. Cloudflare 本機模擬通過不等同正式環境已部署。
5. Generic Demo 完整通過後，才進入真實平台 Adapter 的條款與 selector 評估。
