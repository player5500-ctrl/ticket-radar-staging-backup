# 追票雷達 Ticket Radar — UI／UX 稽核

稽核日期：2026-07-30
稽核方式：登入 Staging（`https://ticket-radar-web-staging.pages.dev`，帳號 `player5500@gmail.com`）以桌面瀏覽器（Claude in Chrome）實測操作與截圖。

## 工具限制說明（誠實揭露）

本輪嘗試用瀏覽器工具的 `resize_window` 切成手機寬度（390×844／400×860）重新截圖，但截圖畫面仍固定回傳桌面寬度（1568px），研判是這組瀏覽器自動化工具的視窗縮放與截圖擷取路徑沒有正確對應，**不是頁面本身不支援 RWD**。因此本輪「手機優先」的稽核，是以桌面瀏覽器實測操作為主，並交叉比對程式碼中是否有響應式 class（Tailwind 的 `sm:`／`md:` 前綴、底部導覽列的存在）作為輔助判斷。底部固定導覽列（首頁／搜尋／任務／紀錄／我的）本身就是手機優先的設計語言，但**實際手機裝置上的按鈕觸控尺寸、鍵盤遮擋、200% 縮放等項目本次未能驗證**，建議後續用真實手機或瀏覽器 DevTools 的裝置模擬模式補測，這點也記錄在 `docs/FINAL_DELIVERY.md` 第 10 節「已知限制」中，並非本次新發現的缺口。

以下逐頁記錄「已實測」與「未實測」，不對未實測項目做任何完成度宣稱。

## 2. 搜尋頁（已實測，發現 P0）

| 項目 | 內容 |
|---|---|
| 頁面 | 搜尋頁 `/search` |
| 問題 | 首次使用者（未曾完整導覽過 API 網域）搜尋後畫面永遠停在「正在掃描演出資料…」轉圈動畫，沒有逾時、沒有錯誤訊息、沒有可操作的按鈕 |
| 嚴重度 | P0 |
| 實際影響 | 使用者會以為網站當機或搜尋功能整個壞掉，直接跳出，不會知道要怎麼解決（根因見 `CODE_FIX_TASKS.md` TASK-01） |

## UI 結論與分類

### A. 不需重新設計（文字/間距/圖示/提示調整即可）

- 搜尋結果的售票狀態標籤加圖示區分（第 3 節）
- 錯誤訊息文案統一與環境區分（第 2、6 節，對應 TASK-05）
- 空狀態文案的維護中提示（第 5 節，過渡方案）

### B. 建議由 Antigravity 做新版原型

本輪**沒有發現**版面資訊架構混亂、主次不清、表單過長等需要重新設計版面的問題——目前看到的頁面（首頁、搜尋、活動詳情、任務空狀態）版面結構本身是清楚的、資訊層級合理。**本次結論：不建議現階段投入 Antigravity 重新設計 UI**，因為主要問題不是「設計不好」，而是「核心按鈕沒接上後端邏輯」與「跨網域驗證架構壞掉」，這些都屬於 C 類（不應交給 Antigravity），應優先交給 Codex／Claude Code 修復程式邏輯。等 TASK-01～04 修復後，若使用者操作完整的建立任務／作戰模式等流程後仍覺得體驗不順，再評估是否需要局部重新設計。

### C. 不應交給 Antigravity 修改

- TASK-01（跨網域 Access 架構）：屬於 Auth／Cloudflare 部署設定
- TASK-02、TASK-03（按鈕無反應）：屬於前端邏輯串接，不是視覺設計問題
- TASK-04（登出後無限 loading）：屬於 Auth／狀態管理邏輯

### 最高優先問題

TASK-01（跨網域 Access 架構讓所有人第一次使用都會卡住）與 TASK-02（建立購票任務按鈕無反應）並列最高優先，兩者任何一個沒修好，都無法完成使用者需求中「建立購票任務→設定預算→…→完成購票準備清單→登出→重新登入確認資料仍存在」這一段核心驗收流程。

### 建議重新設計頁面 / 可直接沿用頁面

- **可直接沿用**：登入後首頁、搜尋頁版面、活動詳情頁版面、購票任務空狀態版面。
- **建議重新設計**：無（本輪未發現版面層級問題，待核心功能修復、走過完整流程後再評估）。
